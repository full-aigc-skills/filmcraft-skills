# FilmCraft 序列工作流与重关联架构

## 事实源与当前状态

既有 OpenSpec FC-DM-001-SEQUENCE 继续管理交接，独立 filmcraft-skills 是技能事实源。当前源码工作流已接入序列登记、原生导入、全帧收集和源工程修订；插件技能快照尚未升级；源码运行时锁现已选择公开 craft.2，见[公开首次使用跟进](FilmCraft-Public-Sequence-First-Use-Architecture.zh_CN.md)。候选测试使用校验摘要的维护版二进制注入安装结果，不冒充公开冷安装。

## 三项原生缺陷与修复

原导入使用默认 29.97 fps；原 Project Manager 只收集首帧；原重关联把首帧按五秒静态图片打开。维护补丁同时保留字幕修复，新增显式有理帧率、逐帧收集和按已保存类型／帧率重关联。缺帧或截断即使指定 force 也不能作为完整序列重关联。普通文件强制重关联行为保持原有范围。

## 工作流合同

输入显式登记 `kind: image-sequence` 和清单摘要，或使用 `--sequence-asset`。工作流不对 JSON 或首帧进行普通媒体 probe，而是校验清单后调用原生 `file.importImageSequence`，核对实际帧数和返回帧率，再读取原生媒体属性，核对类型、时长、尺寸和 Alpha。源工程修订按摘要绑定包内清单和全部帧，以首帧路径原生重关联，并重新检查原生属性。

```mermaid
flowchart LR
    A[清单与全帧校验] --> I[原生序列导入]
    I --> P[读取实际媒体属性]
    P --> T[时间线与预览导出]
    T --> C[原生收集全部帧]
    C --> H[清单与嵌套文件摘要]
    H --> M[移动目录后包内重关联]
    M --> R[局部修订和新交付]
```

## 交付与失败边界

序列资产的 path 指向包内 sequence.json，sha256 绑定其原始字节；sequenceMetadata 保留时间基等声明，probe 来自原生媒体属性。清单 files 包含所有嵌套帧摘要。收集逐帧核对路径和字节，不能只检查首帧。旧工程和旧包只读，修订输出独立目录；坏帧、原生类型或时长冲突不得发布成功结果。

## 真实候选验收

[证据](evidence/sequence-workflow-candidate-20261006.json)：仅复制一个媒体技能，调用真实候选 CLI 完成十二帧序列导入、全帧收集、删除源目录、移动工程后局部移动修订；技能字节与原交付所有文件保持不变，坏帧修订拒绝。独立解码原生 MP4，原片十二帧、移动一帧后的修订十三帧，第六帧颜色对应实际动画时间。目标 1 项通过（1.145 秒）；普通公开固定 CLI 音画／字幕／修订回归 1 项通过（6.277 秒）。原生引擎 285 项通过、三项忽略，默认 Python 43 项通过、十八项门禁跳过。

公开冷安装、固定技能／插件发行、真实 Effect 动态交付接入、Art 依赖与混合修订和创作验收仍需完成。旧候选证据保留其历史补丁摘要，不能证明当前重关联补丁。
